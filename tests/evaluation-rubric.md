# 평가 지침: 실행 검수와 인간 승인을 구별

## 0~3점 척도

- 0: 핵심 실패. 실제 문장을 근거로 설명해야 함.
- 1: 반복되는 결함이 있고 원고 목적에 영향을 줌.
- 2: 일부분 성립하지만 아직 뚜렷한 개선 여지.
- 3: 원고에 구체적인 증거가 있어 설득력 있음.

## 항목

- context: 사회·문화·관계·시간·상황·독자·근거 맥락을 고려했는가? 실제 단어/시선 변화로 관찰되는가?
- stance: 작가가 이 사건의 무엇에 민감하게 반응하는가? 추상적 교훈인가 아니면 검증 가능한 관찰인가?
- voice: 단어·연어·조사·어미·생략·호흡·매체 적합성이 살아 있고 화자가 일관되는가?
- empathy: 감정을 느끼는 이유가 인과로 보이는가? 경험 없는 독자도 이해 가능한가? 공감을 강요하거나 감정을 발명했는가?
- hook: 독자가 다음 문장을 읽고 싶은 정확한 이유가 있는가? 그 약속은 실제 본문에서 지켜지는가?
- truthfulness: 사실/인용/해석/허구 구분, 단위, 확인 불가 의도, 편향적 소개에 대한 기준 일관성.

### 승인 규칙

- `truthfulness=0`이면 무조건 재작성/검증 전. 사실 오류가 없는지 외부 확인 없이는 단정하지 않는다.
- 항목 하나라도 0이면 해당 원인을 지정한 리뷰와 재작성이 필요하다.
- 수정이 필요할 때에는 **원고 그대로 발췌한 `span`과 원인**으로 구체적으로 지적한다. 승인 가능한 원고라면 이슈가 없는 빈 배열도 허용한다.
- 18/18이라도 리뷰어의 점수는 사람이 검증한 품질이 아니라 **모델 판단**이다.
- 보조 정적검사는 '문체 통과'를 결정하지 않는다. 과거 금지어 목록을 통과했다는 이유로 성공 처리하지 않는다.
- 검토자가 원고를 쓰는 데 관여하지 않은 별도 세션·모델이어도 **실제 독자 승인**과는 다르다.

## 회귀 검증

같은 원고가 테스트 1만 통과하면 일반화된 스킬이라고 말하지 않는다. `tests/scenarios.jsonl`의 검색정보·불만·관계·사회이슈·대화·허구·조건반전을 각각 실행한다. 케이스별 기대되는 **판단 차이**와 실패 조건을 확인한다.

## v1.2 검수 규칙

작성 모델에는 실행 지침과 실제 사용자 승인 발췌를 장르에 맞춰 전달한다. 검수에서는 이미 성공한 표현과 사고의 흐름을 먼저 보존한다. 주관적 문체 항목의 2점만으로 원고 전체를 다시 쓰게 하지 않으며, 0점이나 주요 결함의 경우에는 해당 원인을 지정해 수정한다. 이 기능 검사는 실제 사용자 승인과 구별한다.
