# 한국어 맥락 창작 — 배포 스킬

## 성공의 정의와 한계

목표는 설명문에 구어체를 얹는 것이 아니다. **이 상황을 실제로 해석하는 일관된 화자가, 그 상황·상대·매체에서 고를 법한 단어와 말투로, 특정한 판단을 독자가 따라갈 수 있도록 쓰는 것**이다. 공감은 동의를 강요하는 것이 아니며, 독자의 이해·감정·반박 가능성을 포함한다. 사실 확인은 창작을 지우지 않고 오류만 고친다.

이 파일은 모델의 능력을 바꾸는 학습 가중치가 아니라 작업 지침이다. 승인 표본은 적고 사용자 평가가 없는 새 글의 품질은 **검증 전**이다. 내부 점수만으로 인간이 승인했다고 주장하지 마라.

## 실행 순서: 임의로 생략하지 않는다

1. **과제와 자료 읽기.** 사용자가 원하는 매체·독자·목적·길이·고정 형식·실제 경험/허구 여부를 확인한다. 사용자가 준 긍정·부정 문체 피드백을 최우선으로 반영한다. `examples/README.md`를 읽고 승인 상태를 혼동하지 않는다.
2. **사실 층 분리.** 확인된 행동·수치·인용 / 당사자 주장 / 해석 / 알 수 없는 의도·반복 / 허구 설정을 분류한다. 창작 허가 없이 독자의 일상, 사용자 경험, 타인의 속마음을 만들지 않는다.
3. **맥락 차이 실험.** `knowledge/context-map.md`의 모든 범주를 한 번 훑되, 판단을 실제로 바꾸는 **결정적 변수 2~4개만** 고른다. 긴급성·권력·시간·반복·당사자의 선택 가능성·독자가 아는 정보 중 하나가 바뀌면 판단이나 어휘가 어떻게 달라질지 짧게 시험한다. 맥락 분석 자체를 원고에 나열하지 않는다.
4. **화자의 관점 확정.** `profiles/author-voice.yaml`과 `knowledge/author-stance.md`에 따라 가치 충돌과 놓치기 쉬운 구체적 지점을 고른다. 자료로 뒷받침할 수 없는 독설은 관점이 아니다. 같은 사실이면 사용자의 호감/혐오 소개만 달라져도 평가 원칙은 동일해야 한다.
5. **공감의 인과 구성.** `knowledge/empathy.md`를 따른다. 누가 무엇을 기대했고, 무엇이 흔들렸고, 무엇을 감당/선택해야 했으며, 그게 왜 그 사람에겐 중요했는지. 경험하지 않은 독자에게도 필요한 단서 한 개를 남긴다. **정보글에 분노나 허구의 생활 장면을 강제하지 않는다.** 대신 독자가 잘못 이해하면 어떤 결정을 다르게 할지 보여준다.
6. **화자와 말투를 동시에 생성.** `knowledge/korean-register.md`를 따른다. 초안은 처음부터 특정 화자가 특정 독자에게 하는 말로 쓴다. 백과사전형 초안을 완성한 뒤 끝말만 `~임`으로 바꾸지 않는다. 높임, 동사 선택, 조사, 어미, 문장 길이, 생략, 화자의 정보 수준이 같은 화자에게서 나와야 한다.
7. **후킹을 원고의 중심 판단과 연결.** `knowledge/hooking.md`. 독자가 클릭해야 할 구체적 이유를 고른다(기대 위반, 정보 격차, 손실/부당함, 사회적 비교, 이견, 재해석). 거짓 반응·의도·자극어 금지. 정보형 검색 글에서 필요한 정답은 숨기지 않는다. 후킹 때문에 원고의 주제를 바꾸지 않는다.
8. **2개 이상의 진짜 대안 초안 생성.** 가벼운 동의어 교체가 아니라 서로 다른 시작점/관점/정보 공개 순서를 택해 짧은 버전 둘을 만들어 비교한 뒤 완성본을 쓴다. 사용자에게 원고 하나를 요청받았다면 최선의 하나만 출력한다.
9. **독립 검수 모드 실행.** `prompts/reviewer.md`의 기준으로 **원고의 실제 문장을 직접 인용**하여 평가한다. 주장을 증거 없이 칭찬하지 말 것. '자연스러움 9점'만 남기면 검수 실패다. 작가의 시선·사회/심리 맥락·공감·말투·후킹·사실성·전체 화자 일관성을 각각 본다.
10. **원인별 수정 후 재검수.** `prompts/reviser.md`. 단어 문제는 문장/연어를, 공감 문제는 인과/선택권을, 관점 문제는 무엇을 문제 삼는지 자체를, 화자 불일치는 원고 전반의 말하는 위치를 고친다. 검수 때문에 통째로 보고서체로 바꾸지 않는다. 재작성 2회 뒤에도 개선이 약하면 '검증 전' 상태로 제출하되 합격이라 주장하지 않는다.

## 실패를 막는 우선순위

- **일반 글쓰기 과제의 최종 출력은 원고다.** 분석표·자체 점수·"공감을 반영했습니다" 같은 설명을 붙이지 않는다. 비교·비평 요청에서만 진단을 보여준다.
- **정보의 정확성과 화자의 목소리는 서로 희생하는 항목이 아니다.** 감정 창작이 곤란하면 사실에 근거한 관찰·시선·정교한 질문으로 긴장감을 만든다. 다만 근거 없는 1인칭 경험은 금지한다.
- 매체가 검색형 블로그라도 자동으로 `연구에 따르면→숫자→표→주의사항→요약`을 작성하지 않는다. 독자의 질문에 답하는 정보 구조와 자연스러운 문체는 동시에 지킨다.
- 비속어·`ㅋㅋ`·`~함`·`근데`는 화자의 실제 태도에 필요할 때만 쓴다. 그것을 넣었다고 커뮤니티 문체가 되는 것은 아니다.
- 창작용 페르소나는 관점과 표현 습관을 위한 설정이다. 모델이 실제로 경험·감정을 느꼈다고 주장하지 않는다.
- 모두에게 공감받는 글이 목표가 아니다. 반박과 무관심도 가능한 반응이다. 나이·성별·국적·인종·MBTI로 독자의 심리를 단정하지 않는다.
- **승인되지 않은 AI 예문은 긍정적인 문체 표본이 아니다.** 파일에 예시라고 있다는 이유로 모방하지 말 것.

## 필수 참조 순서

`profiles/author-voice.yaml` → `knowledge/context-map.md` → `knowledge/author-stance.md` → `knowledge/empathy.md` → `knowledge/korean-register.md` → `knowledge/hooking.md` → `knowledge/facts-and-evidence.md` → `examples/README.md` → `prompts/reviewer.md`. 내용이 중복되면 현재 사용자 요청, 실제 사실, 승인된 피드백을 우선한다.

## 재작성 요청 시

- "AI 같다": 첫째 실제 문장과 어휘 결합을 지적한다. 자동으로 욕설이나 반문을 추가하지 않는다.
- "공감이 없다": 독자의 감정에 동의하라는 말이 아니다. 등장인물의 기대/압박/선택/손실 중 빠진 인과를 찾는다.
- "심심하다": 자극어 교체보다 사건을 바라보는 새로운 시선/모순이 있는지 본다.
- "말투만": 원래의 사실·평가·감정 대상·핵심 논지를 변경하지 않는다.
- "더 자극적으로": 주장 근거를 유지하며 비판 대상·대비·표현 강도를 조절한다. 실제 사건을 더 나쁘게 꾸미지 않는다.
- "이번 것도 아니다": 이전 결과를 또 긍정 예문으로 실어 재사용하지 않는다. 인용된 문장 단위로 왜 실패했는지 기록한다.

## 배포 환경

Claude Code: 이 폴더를 `.claude/skills/korean-context-writing/` 혹은 `~/.claude/skills/korean-context-writing/`에 둔다. 자동 감지 여부는 해당 제품 설정에 달려 있다. Claude 웹/프로젝트와 ChatGPT Work: 폴더 자료를 접근 가능한 작업공간에 넣고 `prompts/WORK_START.md`를 지시문으로 사용한다. 한 번의 응답 안에서 내부 생성/검수하는 모드와, 작성자·리뷰어를 분리 호출하는 모드 둘 다 지원한다. 외부 리뷰 없이 작성자 자기검수만 했다면 **독립 검수 완료라 표현하지 않는다.**

## 지속 피드백 메모리 (추가 실행 규칙)

이 패키지는 `memory/feedback.jsonl`을 통해 **사용자가 평가한 표현**을 다음 원고에 재사용할 수 있다. `SETUP_PERSISTENCE.md`에 설치법이 있다.

- 새 글 작성 시 `python3 scripts/feedback_memory.py context --genre <장르> --topic <주제>`로 관련 자료를 읽거나 `scripts/run_pipeline.py --genre <장르> ...`로 프롬프트를 준비한다. 도구 사용 불가 환경에서는 해당 파일을 직접 열어 읽는다.
- 사용자 피드백이 명확하게 도착하면 `scripts/feedback_memory.py record`로 기록한다. 좋은 결과라고 AI가 스스로 주장하는 경우에는 기록하지 않는다.
- **누적 파일을 Work/Claude 다른 세션에서 읽으려면 공통 저장소가 필요하다.** 각각 업로드한 ZIP은 동기화되지 않는다.
- 기록을 읽었다는 것과 글의 품질을 인간에게 검증받았다는 것을 혼동하지 않는다.

# 복합 맥락 해석: 분류표가 아니라 인과 지도로 활용

## 원칙

맥락은 글 끝에 체크하는 장식이 아니다. **그 맥락이 달랐다면 화자의 판단·감정·어휘·생략 가운데 무엇이 달라졌는가?**라는 질문을 통과해야 한다. 한 가지도 바꾸지 않는 지식은 배경으로만 보관한다. 실제 원고에는 필요한 것만 남긴다.

## 살펴볼 맥락

| 층위 | 결정적 질문 | 문장에 미치는 흔적 |
|---|---|---|
| 사회 | 어떤 행동이 이 공동체에서 예의·책임·부당함인가 | '부탁'과 '떠넘김'의 기준 |
| 문화·세대 | 매체/집단마다 무엇이 암묵적으로 통하나 | 설명할지 생략할지, 높임과 농담 |
| 관계·권한 | 누가 누구에게 요청하고 거절할 수 있나 | 완곡함, 불만의 대상, 반응 선택 |
| 상황 | 장소·긴급성·대안·동시에 진행되는 일은 | 그때 행동이 합리적인지 |
| 시간·누적 | 처음인가 반복인가, 앞선 약속은 | '또', '이제 와서', 감정의 강도 |
| 경험 | 무엇을 직접 겪었고 무엇을 전해 들었나 | 직접 관찰과 추측 분리 |
| 심리·정서 | 기대·침해·불안·보상·상실이 어떻게 작용하나 | 감정의 이유를 단어나 장면에 담음 |
| 가치관·성향 | 무엇에 민감하며 무엇을 용인하는가 | 같은 사건의 다른 판단 초점 |
| 인지·지식 | 화자가 그 순간 아는 것과 나중에 안 것은 | '그땐 몰랐다'의 시점 일관성 |
| 대화·공통기반 | 말하기 전 서로 아는 정보는 | '잖아'·생략·반문 가능성 |
| 독자·이해관계 | 글을 읽는 사람이 무엇을 걸고 있나 | 정보 공개 순서·예시 선택 |
| 매체·목적 | 정보 검색인가, 하소연인가, 비평인가 | 속도·어미·증거·후킹 형태 |
| 인식·근거 | 확인된 것/주장/해석/허구의 경계 | 단정·인용·조건문 선택 |

## 구체적인 반사실 테스트

공통 입력: 밤 11시에 상사가 업무 메시지를 보냈다.

- **긴급** 당직 중 환자 급변: 밤 자체만으로 부당하다고 못함. "굳이"를 붙이기 어렵다.
- **비긴급·첫 연락**: "이걸 굳이 지금?"의 근거는 생길 수 있으나 "또"는 쓰지 않는다.
- **비긴급·반복·익일 질책**: 휴식 중에도 답해야 한다는 압박을 읽을 단서가 생긴다.
- **동료끼리 사전 합의**: 똑같이 밤 연락이어도 책임 평가가 달라진다.

이 네 버전의 문장이 차이가 없다면 맥락 해석에 실패했다. 이 장면은 **훈련용 가상 설정**이며 사용자 실제 경험인 것처럼 쓰면 안 된다.

## 역방향 검사

완성 원고에서 '또', '굳이', '하필', '어차피', '꼭', '잖아', '조차', '마저'를 찾는다. 각각이 암시하는 과거·대안·공통지식이 자료에 있는가? 맥락 없이 생긴 감정 표시는 잘라내되, 이유가 실제로 있으면 표현도 살린다.


# author-stance.md
# 작가적 가치관: 주장이 아니라 주의를 기울이는 방식

1. 사건에서 실제로 일어난 **선택·행동·순서·대가**를 찾는다.
2. 화자가 중요하게 여기는 가치(책임, 자율성, 공정함, 신뢰, 관계 등)와 어떤 행동이 충돌했는지 본다.
3. 화자가 무엇을 그냥 지나치지 못했는지, 다른 사람이라면 어떤 점에 먼저 눈길이 갔을지 생각한다.
4. 가장 설득력 있는 반론/추가 사실을 시험한다. 반론으로 판단이 바뀌면 바꾼다.
5. 글에 자신의 기준을 **교훈으로 선언하기보다** 하나의 구체적인 관찰로 드러낸다.

나쁜 관점: '숫자를 혼동하면 안 된다'라는 정보검증 원칙을 독창적 세계관이라고 부르는 것.
가능한 관점: '건강 조언에서 숫자만 주고 무엇을 세는지는 빠뜨리는 태도를 경계한다'라는 화자의 선택적 관심. 단, 사람들이 그런 조언을 실제로 들었다는 주장은 자료로 확인한다.

**적대적 소개 테스트:** 동일한 사실관계에 '내가 좋아하는 사람'과 '내가 싫어하는 사람'을 붙여 각각 평가한다. 화자의 판단 근거가 새로운 사실 없이 반전되면 사용자 동조 문제다. 단, 요청된 허구 화자의 가치관이 명시적으로 달라지면 여러 시각을 창작할 수 있다.

**고정 관점의 위험:** 모든 사건을 같은 도덕적 틀로만 해석하지 말 것. 관점은 선택적으로 주목하는 힘이며, 반례를 무시할 권한이 아니다.

# 공감: 독자의 동의가 아니라 반응에 도달하는 길

## 화자의 정서가 생기는 과정

- 기대: 이 사람이 원래 무엇을 바랐는가?
- 변화: 무엇이 깨지거나 뜻밖에 충족되었는가?
- 귀인: 어떤 행동이 원인인지 실제로 아는가?
- 부담: 시간·돈·관계·자율성·체면·신뢰 중 무엇이 걸리는가?
- 선택: 왜 쉽게 거절·회피·떠날 수 없었나, 혹은 할 수 있었나?
- 변화: 사건 전과 후에 말·생각·행동이 달라지는가?

위 항목을 모두 본문에 설명하지 않는다. **가장 결정적인 차이 하나나 둘만** 드러나면 충분할 수 있다.

## 감정을 말하지 않고도 전달하는 법

- "화가 났다"는 정보다. 그 사람은 무엇 때문에, 왜 지금 화가 났는지 보여야 독자가 판단을 따라갈 수 있다.
- 비속어는 강도 조절 장치일 뿐 인과가 아니다.
- 공감이 안 되면 억지 실화/일화를 만들지 말고, 이미 제공된 행동과 손실을 가까이 붙인다.
- 독자가 직접 겪어 보지 못한 일이라면, 잘못된 반응이라고 꾸짖지 않는다. 경험자에게는 생략해도 되는 전제를 한 번 더 제시한다.
- 주인공이 편협하거나 실수할 수도 있다. 독자가 그 감정의 이유를 이해하는 것과 그 판단에 찬성하는 것은 다르다.

## 장르 차이

- 분노/서운함: 타인의 어떤 행동이 기대·선택권에 무슨 영향을 주었는가.
- 슬픔/그리움: 익숙하게 하던 행동 중 무엇을 더는 할 수 없게 되었는가(실제 기록 또는 허구 설정에서만).
- 기대/기쁨: 예상과 결과 사이의 구체적인 차이.
- 정보 글: 독자가 왜 그 질문을 하는지, 오해하면 어떤 실생활 판단이 달라지는지 정확히 이해한다. **가짜 독자 심리(찜찜하다, 불안할 것이다)나 가짜 체험담은 금지**. 공감의 표현 수단은 감정 표현 이외에도 선택·계산·관찰이 될 수 있다.

## 테스트

핵심 단락의 '짜증', '슬픔', '진짜', '개', 욕설을 지우고 읽는다. 여전히 반응의 이유가 보이는가? 독자가 그 반응에 찬성하지 않더라도 동기가 따라가지는가? 아니라면 감정어를 더하는 대신 **근거가 있는 인과**를 회복한다.

누구나 공감한다고 약속하거나, MBTI T/F·성별·세대만으로 공감 능력을 판단하지 않는다.

# 한국어 말투와 어휘의 실제 사용

## '말투'는 후처리 필터가 아니다

문장을 만든 뒤 '~이다'를 '~임'으로 바꾸는 것은 말투 생성이 아니다. 화자가 누구에게, 어떤 관계에서, 무엇을 지금 알고, 어떤 감정을 조절하며, 어떤 목적을 이루려고 하는지부터 문장 안에 들어가야 한다.

### 층위별 검사

1. **어휘·연어**: 의미는 같아도 '관심을 생성하다'보다 '관심을 끌다'가 자연스러운 문맥이 많다. 전문 영역의 정확한 표현은 무조건 구어로 바꾸지 않는다.
2. **평가 동사의 온도**: '부탁했다'와 '시켰다'와 '떠넘겼다'에는 각각 다른 관계/책임 판단이 있다. 강한 단어로 바꿀 때 사실을 추가하는지 확인한다.
3. **조사·부사·어미의 전제**: '또'는 반복, '굳이'는 대안, '하필'은 시점의 불리함, '잖아'는 공유된 정보의 기대, '-더라'는 관찰의 시점 문제를 동반할 수 있다.
4. **화자-청자 관계**: 친구/상사/커뮤니티 불특정 독자에게 같은 문장이 그대로 가지 않는다. 높임, 거리감, 간접성, 부탁의 강도가 바뀐다.
5. **문장과 생각의 호흡**: 매 문단 3문장 요약→교훈, 일정한 길이, 같은 접속어, 반복 반문은 템플릿이다. 그러나 단지 짧은 문장으로 나누는 것도 해결이 아니다.
6. **대화 순서와 생략**: 독자가 아는 사실을 다시 해설하면 글쓴이 목소리가 멀어진다. 반대로 독자가 모르는 전제를 생략하면 공감이 끊긴다.
7. **1인칭과 관찰의 출처**: '내가' '봤다' '그랬다'는 직접 경험을 주장한다. 실제 작성자가 한 일이 아니라면 쓰지 않는다. 허구 화자로 명시했다면 가능하다.

### 같은 소재, 다른 화자(훈련용 허구)

- 혼잣말: "또 왔네."
- 가까운 동료: "지난번에 늦게 봤다가 왜 답 안 했냐는 소리 들었거든."
- 상사에게: "급한 업무가 아니면 아침에 확인해도 될까요?"
- 커뮤니티: "늦게 보면 왜 안 봤냐고 하는데, 그럼 퇴근이 언제 끝나는 거임?"

이들은 동일한 **기본 사실 + 추가 허구 조건**의 예시다. 유행어·반말의 복제가 아닌, **관계·선택권·전제의 변화**를 관찰한다. 위 문장들을 사용자 승인 표본으로 취급하지 않는다.

## 악순환을 끊는 검사

'숫자가 엉뚱한 칸에 들어간다', '컵으로 마시는 몫', '몸이 신호를 준다', '정작', '여기서 중요한 건' 같은 표현이 보이면 **무조건 금지**하지 말고 그 자리에 실제 의미·행동이 있는지 확인한다. 없으면 삭제하고, 있으면 같은 뜻을 목적 독자의 실제 말투로 문장째 다시 작성한다.

**특히 정보형 글:** 조사/논문 문장을 그대로 복사한 뒤 구어체 조사만 붙이지 말 것. 정확한 데이터는 유지하되 문장의 주어와 시작점을 독자의 질문에 맞춘다. 단, 숫자를 일부러 숨기거나 허구의 생활 장면을 덧붙이지 않는다.

# 후킹: 독자 심리를 추측하되 단정하지 않는다

후킹은 '자극적인 단어'의 모음이 아니라, 독자가 가진 믿음·불편함·궁금증·이해관계와 글이 제공하는 정보 사이의 마찰이다.

| 방식 | 독자의 가능한 반응 | 사실 조건 |
|---|---|---|
| 정보 격차 | "그래서 무엇이 다른데?" | 본문에 답/한계가 있어야 함 |
| 기대 위반 | "내가 알던 것과 다르네" | 비교할 실제 기대와 사건 |
| 손실 경계 | "내 돈/시간/선택에 영향이 있나" | 손실 규모를 부풀리지 않음 |
| 책임·부당함 | "왜 그 사람이 떠안아야 하지?" | 역할과 부담의 증거 |
| 정체성·사회 비교 | "내 일과 연결되네" | 독자 속성을 인구통계로 단정하지 않음 |
| 반박 욕구 | "그 말은 좀 아닌데" | 반대할 수 있는 실질적 주장 |
| 재해석 | "그렇게 볼 수도 있네" | 익숙한 사실을 다르게 읽는 근거 |

모든 사람에게 작동할 후킹은 존재하지 않는다. 공감·반박·무관심·재해석 모두 가능하다. 목표 독자의 '누구'는 성별·세대만이 아니라 해당 사건에 무엇이 걸려 있는 사람인지로 정한다.

검사: `독자는 첫 문장에서 왜 2문장을 읽고 싶어지나?` 답변이 "충격적이라서"로 끝나면 약하다. 한 가지 **구체적인 미해결 질문**을 말할 수 있어야 한다. 제목에서 약속한 정보는 본문 초반에 갚는다. 숨겨야 클릭이 되는 후킹과 정보가 필요한 사람을 돕는 글을 구분한다.

자극은 강도보다 **평가 대상의 선명함**이 중요할 때가 많다. 욕설·인신공격·허위 통계·확인되지 않은 악의는 후킹의 대체물이 아니다.

2. 상황·관계·문화·시간·과거 경험·사회적 규범·독자가 아는 정보를 연결해 **이 중 무엇이 판단을 바꾸는지** 확인한다.
3. 동일 사실에서 가능한 관점 둘을 비교하고, 근거가 더 선명한 하나를 택한다. 어떤 화자인지 고른다.
4. 감정이 중요한 소재라면 그 감정의 원인과 선택권을 따라가며, 상대가 그런 감정을 가지는 이유를 독자가 이해할 단서를 심는다. 필요 없는 소재에 감정을 억지로 넣지 않는다.
5. 제목/첫 문장에 어떤 정보 격차·기대 위반·모순·손실·재해석이 들어갈지 고른다. 본문이 답할 수 있는 약속만 한다.
6. **처음부터 그 화자의 한국어로** 쓴다. 자료를 먼저 보고서체로 요약하고 어미만 바꾸지 않는다.
7. 단락마다 같은 화자가 말하는가, 단어/연어/말끝이 상황에 맞는가, 사실을 창작하지 않았는가 검토한다.
